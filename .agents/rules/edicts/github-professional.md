# GitHub Professionalism Edicts

## 1. Repository Presentation
- **README.md**: Must be the "front door". Use images/shields, clear installation steps, and tech stack icons.
- **Description & Tags**: Every repo needs a concise description and relevant topics (e.g., `java`, `spring-boot`, `clean-architecture`).

## 2. Source Control Hygiene
- **Conventional Commits**: Use `feat:`, `fix:`, `docs:`, `chore:`, `refactor:`.
- **Branching**: No direct commits to `main`. Use Pull Requests even when working alone to document progress.
- **Merge Messages**: Keep them clean. Avoid "merge branch...".

## 3. Documentation
- **LICENSE**: Always include a LICENSE (prefer MIT or Apache 2.0).
- **CONTRIBUTING.md**: Even for personal projects, show you know how to work in a team.
- **Architecture Diagram**: Include a Mermaid diagram or image explaining the system design.

## 4. Professionalism
- **Clean Git History**: Use interactive rebase if needed to squash "oops" or "typo" commits before pushing to public.
- **Issue Templates**: Use them to organize your own work/roadmap.
